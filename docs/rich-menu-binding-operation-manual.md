# Rich Menu 身分綁定規則操作手冊

## 1. 這個功能在做什麼

Rich Menu 身分綁定規則用來決定不同 LINE 使用者看到哪一組圖文選單。

平台會同時面對：

- 一般訪客
- 已綁定員工
- 外籍員工
- 待審廠商
- 已核准廠商
- 福委會管理者

如果所有人都看到同一個圖文選單，使用者會走錯流程。例如員工已經完成綁定後，不應該每次都回到註冊首頁；已核准廠商也不應該看到一般訪客入口，而是應該看到廠商專區。

此頁就是用來管理這些套用規則。

## 2. 功能入口

後台路徑：

```text
SAKURA Welfare Admin > LINE OA 專區 > Rich Menu 身分綁定
```

直接網址：

```text
https://sakura-welfare-platform.fangwl591021.workers.dev/rich-menu-bindings
```

## 3. 基本判斷順序

系統會依照「優先順序」判斷。數字越小，越優先套用。

建議順序如下：

1. 管理者 / 福委會
2. 已核准廠商
3. 待審或補件廠商
4. 已綁定員工，依語系套用
5. 未綁定訪客

原因是同一個 LINE 使用者可能同時具有多個狀態。例如某人既是員工又是福委會管理者，這時應優先給管理者選單。

## 4. 預設規則說明

| 使用者類型 | 條件 | alias ID | 用途 |
| --- | --- | --- | --- |
| 管理者 / 福委會 | UID 白名單具管理角色 | `admin_menu` | 後台、審核、監控、報表入口 |
| 已核准廠商 | 廠商審核通過 | `vendor_approved` | 廠商專區、菜單/DM 上傳、核銷、微官網維護 |
| 待審廠商 | 廠商送件中、補件中、退回待修 | `vendor_pending` | 申請表、補件、審核結果查詢 |
| 繁中員工 | 員工綁定成功，語系繁中 | `twmem-menu` | 員工福利、特約店、點數、中文 AI 問答 |
| 印尼文員工 | 員工綁定成功，語系印尼文 | `indo-menu` | 印尼文福利入口與 AI 問答 |
| 泰文員工 | 員工綁定成功，語系泰文 | `taimem-menu` | 泰文福利入口與 AI 問答 |
| 未綁定訪客 | 一般好友、尚未完成身份確認 | `guest_zh` | 員工綁定、廠商申請、公開活動 |

## 5. 欄位說明

### 目標身份

選擇這條規則要套用給哪一類使用者。

可選：

- 訪客 / 未綁定
- 員工
- 廠商
- 管理者 / 福委會

### 語系

用來區分員工或使用者要看到哪一種語言版本。

可選：

- 不限定
- 繁中
- 印尼文
- 印尼文

若是廠商或管理者，通常可以選「不限定」。

### 綁定狀態

用來判斷使用者是否已完成身份綁定。

常用設定：

- 員工：已綁定
- 廠商：已綁定
- 訪客：未綁定

### 廠商審核狀態

只有目標身份為「廠商」時才主要使用。

常用設定：

- 待審 / 補件
- 已核准
- 退回
- 停權

### 管理者角色

只有目標身份為「管理者 / 福委會」時使用。

可填：

```text
admin,committee,operator
```

實際角色名稱需與 UID 白名單設定一致。

### 本頁 alias ID

這是圖文選單的識別名稱，方便管理與切換。

範例：

```text
twmem-menu
vendor_approved
admin_menu
```

注意：alias ID 不是 LINE 真正綁定使用者時使用的 richMenuId。

### LINE richMenuId

這是 LINE 官方回傳的圖文選單 ID。

正式要把某個使用者綁定到指定 Rich Menu 時，需要使用這個值。

如果目前還沒部署該選單，可以先空白，但正式上線前必須補上。

### 優先順序

數字越小越優先。

建議：

```text
管理者：100
已核准廠商：180
待審廠商：200
繁中員工：300
印尼文員工：310
泰文員工：320
訪客：900
```

### 狀態

可設定：

- 啟用
- 停用

停用後，該規則不會被套用。

### 規則說明

給管理者看的說明文字，建議寫清楚這條規則的使用對象與限制。

### 套用時機標註

用來說明系統什麼時候應該重新套用 Rich Menu。

範例：

```text
員工綁定成功、語系切換為印尼文。
```

## 6. 新增一條規則

操作步驟：

1. 點選「新增規則」。
2. 選擇目標身份。
3. 選擇語系與綁定狀態。
4. 填入 alias ID。
5. 若已部署 LINE Rich Menu，填入 richMenuId。
6. 設定優先順序。
7. 填寫規則說明與套用時機。
8. 點選「儲存規則」。

儲存後，左側清單會出現該規則。

## 7. 編輯既有規則

操作步驟：

1. 在左側清單找到要修改的規則。
2. 點選「編輯」。
3. 右側表單會帶入目前內容。
4. 修改欄位。
5. 點選「儲存規則」。

## 8. 停用規則

若某個選單尚未完成，或暫時不想套用：

1. 在該規則右側點選「停用」。
2. 狀態會變成停用。

停用不會刪除資料，日後可再啟用。

## 9. 刪除規則

若規則已不再使用：

1. 點選「刪除」。
2. 確認刪除。

注意：刪除後不會自動還原。若只是暫時不用，建議使用「停用」。

## 10. 重建預設規則

「重建預設規則」會清空目前規則並重新建立系統預設規則。

只有在以下情況建議使用：

- 測試環境重置
- 規則被改亂，需要回到標準狀態
- 系統商重新部署初始設定

正式營運中不建議隨意使用，避免覆蓋已調整好的規則。

## 11. 常見情境範例

### 情境一：員工綁定完成後不要回首頁

設定：

```text
目標身份：員工
語系：繁中
綁定狀態：已綁定
alias ID：twmem-menu
優先順序：300
```

當員工完成工號 + 生日四碼驗證後，系統應重新套用 `twmem-menu`。

### 情境二：印尼員工看到印尼文選單

設定：

```text
目標身份：員工
語系：印尼文
綁定狀態：已綁定
alias ID：indo-menu
優先順序：310
```

當員工語系為印尼文時，套用印尼文 Rich Menu。

### 情境三：廠商審核通過後看到廠商專區

設定：

```text
目標身份：廠商
廠商審核狀態：已核准
alias ID：vendor_approved
優先順序：180
```

廠商審核通過後，系統應切換到廠商專區選單。

### 情境四：待審廠商只能補件與查結果

設定：

```text
目標身份：廠商
廠商審核狀態：待審 / 補件
alias ID：vendor_pending
優先順序：200
```

未核准前，不提供完整廠商經營功能。

## 12.1 部署與預設首頁的邊界

Rich Menu 編輯器的「部署至 LINE」只負責建立或更新 LINE Rich Menu、圖片、alias 與 D1 專案紀錄。一般部署不應改變全體使用者的預設首頁。

全域預設 Rich Menu 只保留給未綁定訪客首頁：

```text
alias ID：guest_zh
```

操作規則：

1. 部署員工選單 `twmem-menu`、`indo-menu`、`taimem-menu` 時，不勾選「設為訪客預設選單」。
2. 部署廠商或管理者選單時，不勾選「設為訪客預設選單」。
3. 只有要更新未綁定訪客首頁時，才可在 alias ID 為 `guest_zh` 的專案勾選「設為訪客預設選單」。
4. 員工、廠商、管理者看到的選單，應由身分綁定規則呼叫 LINE link API 套用，不由全域預設控制。

驗收重點：部署非 `guest_zh` 選單後，既有員工、廠商與管理者不應被洗回該選單；未綁定訪客首頁也不應被改變。
## 13. 驗收方式

### 後台規則驗收

1. 開啟 Rich Menu 身分綁定頁。
2. 確認有 7 條預設規則。
3. 新增一條測試規則。
4. 儲存後重新整理。
5. 確認規則仍存在。

### 欄位驗收

確認每條規則至少能看到：

- 目標身份
- 語系
- 綁定狀態
- 廠商狀態
- alias ID
- richMenuId
- 優先順序
- 規則說明
- 套用時機

### 上線前驗收

正式上線前，每條啟用規則都應補上 LINE richMenuId。

若缺少 richMenuId，只能作為管理規則，不能正式綁定 LINE 使用者。
