# 櫻花福委會 AI 工作台 PRD

- 文件名稱：AI Workspace Product Requirements Document
- 專案：櫻花福委會福利資訊整合平台
- 版本：V1.0
- 狀態：規劃版
- 更新日期：2026-08-03

## 1. 產品定位

AI 工作台是 LINE OA 聊天室與既有管理後台之間的智慧工作入口。它不重做 Admin UI，也不取代母站、子站或既有審核流程，而是整理即時狀態、提示優先工作，並把使用者帶到正確的 Flex Message、LIFF／Popup 或完整後台。

一句話定義：系統主動整理工作、提出建議，並引導使用者完成任務，而不是要求使用者先學會整套後台。

## 2. 背景與問題

平台已有廠商申請與審核、優惠管理、活動報名與 QR 報到、消費核銷、分眾推播、聊天室監控、關鍵字規則及營運報表。主要問題不是缺少功能，而是功能分散、操作入口多、教學成本高，且管理員仍需自行判斷今日優先事項。

## 3. 設計目標

1. 管理員在 LINE OA 輸入「儀表板」即可取得即時營運摘要。
2. 目標版本以 Flex Message 呈現數據、風險與工作入口。
3. 填表工作透過 LIFF／Popup 完成，結果回到聊天室摘要。
4. 依角色與資料權限顯示不同內容。
5. 高風險寫入必須預覽、二次確認並保留稽核紀錄。
6. 不破壞既有 Admin UI、單一 replyToken 責任及母子站權限邊界。

## 4. 使用角色

### 4.1 福委會管理員

可查看完整儀表板、待審廠商、活動、推播、聊天室與風險資訊。管理員是 V1 的主要使用者。

### 4.2 合作廠商

只可查看及操作自己店家的申請、補件、優惠、微官網、核銷與成效。不得存取其他廠商或全體營運資料。

### 4.3 一般員工／會員

V1 不提供管理功能，只保留福利、活動、報名、消費紀錄及問題反映等既有服務。

### 4.4 系統管理員

維護 LINE、Webhook、D1、R2、LIFF、Secrets 與系統權限。高權限系統設定仍使用現有後台。

## 5. 核心功能

- 營運儀表板：待審廠商、上架優惠、今日核銷、待回覆、風險及到期事項。
- 新增活動：LIFF 表單、圖片、社團、名額、資格、QR 報到及發布確認。
- 分眾推播：受眾條件、預估人數、訊息預覽、立即／排程與二次確認。
- 廠商審核：資料摘要、缺件、AI 建議、通過／補件／暫緩及稽核。
- 聊天室監控：未回覆、高風險、摘要、建議回覆與人工接手。
- 風險中心：抱怨、重複事件、核銷爭議、API 異常及人工處置。

## 6. AI 原則

1. **先驗證再查詢**：未通過 UID 與角色驗證，不查管理資料。
2. **確定性優先**：已知關鍵字先走規則路由，AI 只處理摘要、分類與建議。
3. **唯讀預設**：V1 不執行業務資料寫入。
4. **人類最終決策**：通過、退回、推播、下架等動作必須由管理員確認。
5. **不虛構數據**：數字只能來自正式資料來源；查詢失敗要明示。
6. **最小揭露**：只顯示完成任務所需的最少個資與營運資訊。
7. **可稽核**：未來寫入操作須記錄操作者、時間、輸入、結果與影響範圍。
8. **單一回覆責任**：不得重複消耗 LINE replyToken。
9. **母子站邊界**：母站掌管員工身分與點數；子站掌管廠商、福利、活動、核銷與營運。

## 7. 非目標

- 不重構或取代現有後台。
- 不建立第二套員工驗證或點數系統。
- 不在 V1 導入自由型自主代理。
- 不允許 AI 自動大量推播、扣點、退款、刪除、停權或審核。
- 不一次把所有後台功能搬進聊天室。

## 8. 成功指標

- 儀表板使用次數及管理員回訪率。
- 由 LINE 完成任務的比例。
- 活動建立、推播及補件平均處理時間。
- 未回覆訊息與風險事件平均發現時間。
- 誤操作率、重複送出率與管理員滿意度。

## 9. 現況與目標差距

目前 Phase 1 已有精準關鍵字、管理員白名單及唯讀純文字摘要。Flex Dashboard、Workspace Popup、AI 今日建議與寫入型工作入口屬後續階段，未完成前不得在驗收報告中標示為已上線。
