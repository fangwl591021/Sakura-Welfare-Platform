# 櫻花福委會 AI 工作台驗收表

- 版本：V1.0
- 更新日期：2026-08-03

## A. Phase 1 功能驗收

| 編號 | 測試情境 | 預期結果 |
|---|---|---|
| A01 | 白名單管理員輸入「儀表板」 | 收到即時摘要 |
| A02 | 白名單管理員輸入「仪表板」 | 收到相同口徑摘要 |
| A03 | 非管理員輸入關鍵字 | 僅收到無權限提示，不取得管理數據 |
| A04 | 輸入「查看儀表板」等近似文字 | 不誤觸 Workspace Intent |
| A05 | D1 有待審廠商與核銷資料 | 摘要數字與後台同口徑 |
| A06 | 跨台灣午夜查詢 | 今日核銷使用 Asia/Taipei 日期 |
| A07 | 重複輸入關鍵字 | 每次只回覆一次，不重複消耗 replyToken |
| A08 | 執行儀表板查詢前後比對 D1 | 業務資料無新增、修改或刪除 |

## B. 安全與權限驗收

| 編號 | 驗收項目 | 通過標準 |
|---|---|---|
| B01 | 管理員識別 | 僅以有效 LINE UID 與啟用白名單判斷 |
| B02 | 最小揭露 | 無權限回覆不揭露數字、UID 清單或角色設定 |
| B03 | 母子站邊界 | 不直接修改母站員工或點數資料 |
| B04 | Secrets | 原始碼、文件與日誌不含 Token、Secret 或 API key |
| B05 | 單一回覆責任 | Workspace 不建立第二個 replyToken owner |

## C. 回歸驗收

- 原有母站關鍵字仍可運作。
- 廠商申請、廠商專區、Rich Menu、聊天監控及核銷流程未被攔截。
- Admin UI 頁面與權限未更動。
- Webhook intake 與監控資料仍可記錄。
- D1、R2 binding 與部署目標未更動。

## D. Phase 1.1 Flex 驗收

- Flex JSON 通過 LINE 驗證。
- 手機版與桌面版不溢位、不空白。
- 顯示待審、優惠、核銷、待回覆、風險與到期資訊。
- 顯示 AI 建議時明確標註為建議。
- 五個工作入口可開啟正確 Popup／LIFF 或下一層 Flex。
- 單一模組失敗時仍顯示其餘摘要。

## E. 寫入功能共同驗收

新增活動、分眾推播、廠商審核及風險處理在正式上線前，逐項確認：

1. 角色與資料範圍驗證。
2. 輸入驗證與錯誤提示。
3. 最終預覽與影響範圍。
4. 二次確認。
5. 冪等與連點防重複。
6. Audit Log。
7. 成功、部分成功與失敗摘要。
8. 回滾或補救方式。
9. 白名單實機測試。

## F. 交付證據

每次交付需附：

- 修改檔案清單。
- 實際執行的測試指令及結果。
- 是否部署、版本 ID 與網址。
- 是否執行 migration、Remote D1 write、Secret／Binding 修改。
- LINE 手機與桌面驗收截圖或紀錄。
- 已知問題與下一步。

## G. 發布判定

- **GO**：全部必要驗收通過，無未處理的權限、資料錯寫或 replyToken 風險。
- **CONDITIONAL GO**：僅有明確不影響核心流程的顯示問題，且有回復方案。
- **NO-GO**：權限繞過、重複回覆、錯誤資料寫入、母子站越權、重複推播或不可回滾。
